# 家計簿（開発名 kakeibo-app）

**使える額を見ながら、収入・支出・資産を記録する、自分用の家計簿。** らくな家計簿の後継。スマホ主体のPWA。

- 公開URL（予定）：https://kirokubox.github.io/kakeibo-app/
- 要件の正本：`05_開発・Webアプリ/17_家計簿/176_家計簿_要件と経緯.md`、初期仕様：`171_家計簿_初期仕様.md`
- 現在は v0.8.0（段階8：検索・集計・AI用Markdown・サブスク見直し・カード照合とCSV取り込みまで）。全8段階のうち、段階1〜6（v0.6.0）が公開済み、段階7（変換スクリプト＝`tools/convert-mmbak`）と段階8が実装済み（段階2：資産・分類・設定、段階3：入力と明細、段階4：振替・カード・立替・残高修正、段階5：繰り返し・給料明細・休日の移動、段階6：使える額・予算・取り置き・予定出費・ホーム・見通し）

## できること（段階8）

- 検索：明細タブの虫めがね。内容・メモ・立替の相手を、全角半角・かな／カナの違いを区別せず、空白区切りで「すべて含む」。絞り込みは期間・資産・分類（大分類を選ぶと小分類すべて）・金額・タグ・種類。結果の件数と合計（明細タブと同じ数え方）。日のまとまりで新しい順、押すと編集（`src/searchLogic.ts`、`src/SearchView.tsx`）
- 集計タブ：週・月・年・任意（月・年は暦月・暦年）。合計の帯、分類別の円グラフ（上位8つ＋その他）と一覧→小分類→月ごとの推移（直近12か月の折れ線）と明細、タグ別（横棒＋12か月の積み上げ棒）、週・月の予算と使った額、月ごとの収入と支出、資産の月末残高の推移、残高修正の回数と金額。グラフはSVGで手描き（`src/Charts.tsx`、ライブラリなし）。計算は `src/summaryLogic.ts`
- サブスク見直し：集計タブの下。固定費＞サブスクを内容ごとにまとめ、「続ける／やめる」を `subscriptionReviews` に記録（DBの版2）。最後の見直しから90日（初回は使い始めて90日後）でホームにお知らせ。「やめる」にした後も支払いが続いていれば警告（`src/subscriptionLogic.ts`、`src/SubscriptionView.tsx`）
- AI用Markdown：設定の「AIに渡す書き出し」。週・月・任意。期間のまとめ、予算と実績、分類別、明細（メモ・立替・返金・取り置き・見込み額・手数料・繰り返し・給料明細）、未回収の立替・取り置き・予定出費。表のセルの `|` は `\|`、改行は `<br>`。ファイル名 `kakeibo-ai-開始日_終了日.md`（`src/aiMarkdown.ts`、`src/AiExportCard.tsx`）
- カードの照合：資産の明細（カード）の「照合」。請求の日付と請求額を入れ、照合していない明細（そのカードの支出・返金・残高修正）にチェックして差額を0に。差額は「残高修正にする」か明細を直す。確定で `CardStatement` を作り、`reconciledStatementId` を付け、引き落としの振替を作る／作らないを選ぶ（同じ月にカードへの振替があれば知らせる）。︙「照合の履歴」から取り消せる（振替は残す）（`src/reconcileLogic.ts`、`src/ReconcileView.tsx`、`src/StatementHistoryView.tsx`）
- カード明細CSV（楽天e-NAVI）：照合画面の「明細のファイルから」。Shift_JIS・UTF-8を読み、列は見出しから探す（見つからなければ選ぶシート）。金額と日付（±3日）で1対1、まとめて入れた分（複数行＝1件）、分けて入れた分（1行＝複数件）を照合し、合わないものだけ出す。CSV側だけの行は「支出として入れる」。ファイルは保存しない（`src/csvImport.ts`）
- 追加インポートの確認に、変換スクリプトのJSONの `source` から「取り込み元：らくな家計簿」と明細の件数を出す（`source` は任意。`src/importPreview.ts`）
- DBの版2：`subscriptionReviews` ストアを足すだけ（既存のストアとデータには触れない。`src/dbMigration.ts`）。版2より前のバックアップも読める

## できること（段階6）

- 使える額：使える資産 − 生活防衛資金 − 取り置き残高 − 決まった出費（給料日の前日までに予定されていて、まだ明細になっていない繰り返しの支出・含めない資産への振替・予定出費）。期限は次の給料日で、それより前の収入は足さない。1日あたり・残り日数も出す（`src/budgetLogic.ts`）
- 週と月の予算：週の予算は月曜の時点の1日あたり × 7日（給料日をまたぐ週は給料日の前日まで＋給料日から日曜まで）。月の予算は給料日の区切りなら、給料が入ってから給料日の時点の使える額で決める。ホームの︙「今の額で決め直す」で決め直せる。`BudgetSnapshot` に保存
- 取り置き：作る・入れる・戻す・閉じる・出し入れの履歴。支出の入力の「取り置きから払う」で、取り置きの残高から払える（`src/reserveLogic.ts`）
- 予定出費：月・金額・取り置きとの結びつき、済みにする（`src/plannedLogic.ts`）
- ホーム：今週あと◯円（または今週使った額）、給料日までに使える額（内訳つき）、今月の予算、取り置き・未回収の立替、お知らせ、最近の明細
- 見通し：給料日ごとの3か月／6か月の表（期のはじめの使える資産・収入・決まった出費・予定出費・変動費の見込み・期末の見込み）、予定出費、取り置き（`src/outlookLogic.ts`）

## できること（段階5）

- 休日の移動：土日と祝日（`src/holidays.ts`。キロクカレンダーの祝日計算を写したもの。年ごとの更新は不要）を休日として、「前の平日／後の平日／そのまま」で日付を動かす（`src/businessDay.ts`）。給料日・カードの引き落とし日・繰り返し・給料明細で使う
- 繰り返し：入力画面の日付の右の「繰り返し」から作る。日が来たら、アプリを開いたとき・画面に戻ったとき・日付が変わったときに明細を自動で作る（`generatedThrough` で二重に作らない）。見込み額の印、設定の「繰り返し」で一覧・編集・終了・削除
- 給料明細：設定の「給料明細」でひな形（支給・控除・精算の行）を作り、毎月の明細1枚分をまとめて入れる。あとから1枚まるごと直せる
- 先の予定の日付（`src/scheduleLogic.ts`。段階6の見通しが使う）、資産タブのカードに「次の引き落とし 11/27(金)」

## 開発

```
npm install
npm run dev        # http://127.0.0.1:5173/kakeibo-app/
npm run build      # 型チェック＋本番ビルド（変更後は必ず通す）
npm test           # 純粋ロジックのテスト（node --test）
npm run preview    # ビルド結果の確認
```

スマホ実機確認（PCと同一Wi-Fi）：`npm.cmd run dev -- --host 0.0.0.0`

## データ保存とバックアップ

- 保存先はブラウザの IndexedDB（DB名 `kakeibo-app`）。**この端末のブラウザ内だけ**で、サーバー・クラウド・ログイン・自動同期はない
- 起動時に `navigator.storage.persist()` を要求する（ブラウザの自動削除を防ぐだけ。「Cookieとサイトデータ」の削除や機種変更では消える。同じ kirokubox.github.io の他のアプリもまとめて消える）
- 設定画面の「バックアップを保存」で `kakeibo-backup-YYYY-MM-DD.json` を書き出す。定期的に保存する
- **バックアップのJSONは個人データ。リポジトリ・`public/` に置かない・gitに入れない**（`.gitignore` で `kakeibo-backup-*.json` を除外）。置き場所は `05_開発・Webアプリ/17_家計簿/backup_json/`
- テストは架空データだけを使う

## 公開（GitHub Pages＋PWA）

- `main` に push すると GitHub Actions（`.github/workflows/deploy.yml`）が Pages へ自動デプロイ
- Vite の `base` は `/kakeibo-app/`（リポジトリ名に一致させる）
- Service Worker はビルドごとに版番号を刻印（`vite.config.ts` のプラグイン）。新しい版を検知したら自動で切り替えてリロードする
- `robots.txt` は `Allow: /`（公開前提・検索インデックス許可）
